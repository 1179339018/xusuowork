矛盾纠纷管理系统

一个面向基层治理的小程序，把纠纷录入、街道分派、社区回访、状态更新和操作留痕串成一条清晰的业务闭环。

4核心角色
10小程序页面
5核心数据表
18云函数模块
主业务链路
发现纠纷到闭环处理
录入后进入待分派，街道分派到社区，社区回访后更新状态并形成记录。
技术栈
uni-app + Vue 3 + Pinia + uniCloud
前端负责页面与交互，云函数承载登录、查询、分派、回访和管理能力。

角色分工

系统通过角色决定用户能看什么、能做什么。管理员负责配置，街道负责分派，社区负责回访。

警

派出所

负责录入纠纷，查看自己录入事项的后续分派和处理进度。

街

街道

查看待分派纠纷，选择社区承接任务，并跟踪整体处理进度。

社

社区

查看分派到本社区的任务，提交回访记录、处理措施和结果。

管

管理员

维护用户、角色和社区归属，查看全局数据和任务流转情况。

纠纷流转

一条纠纷从录入开始，经过街道分派和社区回访，最终进入已化解或继续跟进。

1

录入纠纷

填写来源、社区、标题、描述、位置、风险等级等信息。

2

进入待分派

系统写入 disputes 表，状态默认为待分派。

3

街道分派

街道选择承接社区，记录分派信息和操作日志。

4

社区回访

社区提交回访方式、措施、备注、照片或录音。

5

状态闭环

根据回访结果变为已化解、处理中或继续待回访。

数据关系

disputes 是主表，users 决定身份，feedbacks、logs、assignments 记录处理过程。

users

保存授权用户、openid、手机号、角色和社区归属。

openid phone authorized_roles community

disputes

纠纷主记录，承载状态流转、位置、风险等级和分派社区。

title / description status / urgency create_user assign_community

过程记录

回访、分派和日志用于还原每一步操作。

feedbacks logs assignments

云函数分层

云函数按登录、业务流转、管理统计三类组织，是后续安全和性能优化的重点。

登录身份

login / checkBind

负责微信 code 换 openid、手机号绑定、启动时识别用户身份。

纠纷业务

push / assign / feedback

负责新增纠纷、街道分派、社区回访和状态更新。

管理统计

adminManager / statistics

负责用户管理、角色配置、首页和列表统计数据。

后续优化路线

下一步最值得做的是安全权限，其次是列表和详情性能，最后再做视觉统一。

P0 安全

服务端权限收口

详情、列表、录入、回访都应由云函数根据当前 openid 查询用户身份，再判断可见范围和操作权限。

P1 性能

分页、索引、懒加载

用户管理加分页，详情页回访和日志懒加载，确认 disputes 和 users 常用查询索引。

P2 体验

页面视觉统一

继续统一录入、详情、登录、分享页，让系统从能用走向稳定、清晰、专业。

一句话总结： 当前项目已经具备完整业务骨架，最重要的下一步不是继续堆功能，而是把权限、查询性能和页面结构继续收紧，让系统更接近企业级交付状态。
